# WENIT! 시연 대본

발표 시연용 MVP 를 무대에서 보여 주는 순서다. 값과 시간은 에뮬레이터 리허설 기준이며, 실기기에서는 아직 확인하지 못했다(`docs/VERIFICATION_LOG.md` 8단계).

## 1. 사전 점검 (시연 30분 전)

| 항목 | 확인 방법 | 비고 |
|---|---|---|
| 접근성 켜짐 | 설정 > 권한 상태 "켜짐", 홈 "감지 중" | 꺼져 있으면 홈에 빨간 경고가 뜬다 |
| 알림 허용 | 설정 > 권한 상태 "허용됨" | 팝업을 끈 경우 유일한 개입 경로다 |
| 배터리 절약 꺼짐 | 시스템 설정 | 서비스가 멈출 수 있다 |
| 방해 금지 모드 | 시스템 설정에서 켜고, WENIT! 는 예외로 허용 | 다른 앱 알림이 무대에 뜨지 않게 한다 |
| 네트워크 | 설정 > 지금 분석 또는 목표 추천을 한 번 실행 | 공용 와이파이 대신 핫스팟을 준비한다 |
| API 크레딧 잔액 | Anthropic 콘솔에서 확인 | 앱에서는 잔액을 볼 수 없다. 한 번 시연에 2~3회 호출한다 |
| 유튜브 로그인 | YouTube 앱에서 쇼츠 재생 | 로그인 창, 광고 동의 창이 끼지 않는지 본다 |
| 화면 미러링 | 미러링 켠 채 팝업까지 확인 | 팝업이 미러링에 나오는지 본다 |
| 시연 모드 기준 시간 | 개발자 화면 > 시연 모드 기준 시간 | **무대는 20초 또는 30초 권장.** 앱 기본은 10초다 |

개발자 화면 여는 법: 설정 맨 아래 "버전 0.1.0" 을 7번 누른다. 디버그 빌드에서만 열린다.

## 2. 시연 순서 (약 7~10분)

| # | 동작 | 화면 | 말할 내용 |
|---|---|---|---|
| 1 | 개발자 화면 > **온보딩부터 다시 시작** > 초기화 | 설문 1/6 | 무대 올라가기 전에 해 둔다. 기록·정책·설문·동의·목표가 지워진다 |
| 2 | 설문 6문항 응답 | 설문 | "화면을 보지 않고도 시작할 수 있게 짧게 물어봅니다" |
| 3 | 동의해요 | 동의 | 보내는 것과 보내지 않는 것을 짚는다 |
| 4 | 다음 (권한 확인) | 권한 | "화면 글자나 댓글은 저장하지 않습니다" |
| 5 | AI 추천 대기(약 5~8초) 후 카드 고르고 시작 | 목표 추천 | "설문으로 만든 목표입니다. 고르는 건 사용자입니다" |
| 6 | 설정 맨 아래 **시연 모드** 켜기 | 설정 | 초기화는 시연 모드를 끄지 않는다. 켜져 있으면 넘어간다 |
| 7 | YouTube 쇼츠 재생 | 쇼츠 | "지금은 쇼츠를 보는 중이라고 추정합니다" |
| 8 | 기준 시간 뒤 Lv.1 팝업 > **계속 볼래** | Lv.1 | "가볍게 알려 줍니다" |
| 9 | Lv.2 > 이유 하나 고르고 **조금만 더** | Lv.2 | "이유를 고르기 전에는 버튼이 눌리지 않습니다" |
| 10 | 약 30초 뒤 Lv.3, 숨 고르기 10초 대기 | Lv.3 | "넘기면 조금 더 강해집니다. 끄는 것도 사용자가 할 수 있습니다" |
| 11 | **오늘은 여기까지** | 홈 | "N초에서 멈췄어요" 카드를 보여 준다 |
| 12 | 개발자 화면 > 시나리오 A 넣기 > 이전 | 개발자 | "2주치 예시 기록입니다. 실제 기록이 아닙니다" 라고 밝힌다 |
| 13 | 기록 탭 | 기록 | "지난주보다 늘었습니다"(시연 요일에 따라 값이 다르다. 리허설 수요일 89%) |
| 14 | 설정 > **지금 분석**, 약 5~8초 대기 | 설정 | "AI 는 정해진 범위 안에서만 정책을 바꿉니다" |
| 15 | 기록 탭 > 개입 방식 변경 이력 | 기록 | 바뀐 값과 이유, **되돌리기** 버튼을 보여 준다 |
| 16 | (시간 있으면) 개발자 화면 > **시연 준비 초기화** > 시나리오 B 넣기 > 이전 > 지금 분석 | 기록 | A 와 달리 지난주보다 줄었고, 조금 늦게 알린다 |

리허설 결과(에뮬레이터, 2026-11-04):

| 시나리오 | 지난주 대비 | 분석 결과 | 응답 시간 |
|---|---|---|---|
| A | 89% 늘었어요 | 기준 180→120초, 단계 1→2, 상한 10→8회 | 6.6초 |
| B | 79% 줄었어요 | 기준 180→210초 | 6.0초 |

AI 응답이라 숫자와 문구는 호출마다 달라질 수 있다. 대본은 "방향"(A 는 조이고 B 는 푼다)만 말하고 숫자를 외우지 않는다.

## 3. 주의

- **시나리오 전환 전에 반드시 시연 준비 초기화.** 안 하면 A 와 B 기록이 섞이고 아낀 시간 기준값도 앞 시나리오에 고정된다.
- **실제 개입 하루 상한.** 기본 10회이고 에이전트가 낮출 수 있다. 시연 모드 개입은 따로 센다. 팝업이 안 뜨면 시연 준비 초기화로 오늘 횟수를 0 으로 만든다.
- **AI 응답은 5~8초.** 누른 뒤 침묵하지 않게 멘트를 준비한다. 시간 제한은 15초다.
- 지금 분석은 시나리오를 넣은 뒤에만 의미가 있다. 개입이 3건 미만이면 "개입 기록이 아직 적어서 분석하지 않았어요" 가 나온다.
- 시나리오의 오늘 몫은 시각이 지난 뒤에만 들어간다. A 는 01:25 이전, B 는 07:34 이전에 넣으면 오늘 몫이 빠져 월요일 이른 시각에는 A 의 비교 방향이 달라질 수 있다.
- 개발자 화면을 연 채 다른 탭으로 나가면 설정 탭을 눌렀을 때 개발자 화면이 다시 나온다. **이전** 으로 나온다.
- 네트워크가 끊겼다 돌아오면 YouTube 가 쇼츠 플레이어가 아닌 목록을 보여 줄 수 있다. 이때는 감지되지 않는 것이 정상이므로 영상을 하나 눌러 재생한다.
- 멈춤 카드는 닫기, 날짜 변경, 새 쇼츠 세션 시작에 사라진다. 11번 뒤 쇼츠를 다시 틀었다면 카드가 없는 것이 정상이다.

## 4. 비상 대책

| 상황 | 화면 | 대처 |
|---|---|---|
| 목표 추천 실패 | "AI 추천을 받지 못해서 기본 추천으로 보여 드려요." | 그대로 진행한다. 멘트: "AI 가 실패해도 앱은 멈추지 않고 기본 추천으로 이어 갑니다" |
| 지금 분석 실패 | "분석하지 못해서 지금 정책을 그대로 쓰고 있어요." | 멘트: "실패하면 정책을 바꾸지 않습니다". 네트워크를 고쳐 한 번만 다시 누른다 |
| 네트워크 불가 | 위 두 안내 | 핫스팟으로 바꾼다. 안 되면 2~11번만 라이브로 보이고 12~16번은 백업 영상으로 넘긴다 |
| 팝업이 안 뜸 | 홈 "감지 중" 확인 | 쇼츠 플레이어 화면인지 본다 > 시연 모드 켜짐과 기준 시간을 본다 > 시연 준비 초기화 |
| 접근성 꺼짐 | 홈 빨간 경고 | 설정으로 가기 > 시스템 접근성에서 켠다 |
| 앱 또는 기기 문제 | - | 백업 영상으로 바꾼다 |

**백업 영상:** 리허설 때 2~16번 전체를 화면 녹화해 둔다. 영상에 다른 사람의 쇼츠 내용이 나오므로 발표 자료로만 쓰고 공개 게시하지 않는다.

## 5. 시연 전 정리

- [ ] 10초 기준 값은 개발자 화면에서만 고를 수 있다(온보딩과 설정 화면에는 기준 시간 선택이 없다, 2026-11-04 확인).
- [ ] 개발자 화면은 디버그 빌드에서만 열린다. 시연에 디버그 APK 를 쓰므로 **디버그 APK 를 외부에 배포하지 않는다.** API 키가 빌드에 들어간다.
- [ ] 실기기에서 전체 순서를 한 번 리허설한다(미검증).
- [ ] Google Play 배포 전 접근성 API 선언·고지·동의 요건은 별도 검토가 필요하다. 이번 시연 범위가 아니다.
