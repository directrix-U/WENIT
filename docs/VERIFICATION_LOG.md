**에뮬레이터에서 찾아 고친 문제**
1. 트리 순회는 `reel_watch_player` 를 찾지 못했다(접근성상 "중요하지 않은" 뷰). 기존과 같은 ID 검색으로 되돌렸다.
2. 순회 비용이 컸다. YouTube 는 ID 검색만 하도록 바꿨다.
3. 대상 앱 대화상자를 이탈로 처리했다. `OVERLAY` 가림으로 바꿨다.
4. 홈 버튼 뒤 PiP 플레이어(0.077)를 "가림"으로 계속 유지했다. `PLAYER_MINIATURE` 로 이탈 처리하도록 바꿨다.
5. 쇼츠 스크롤 이벤트에 인덱스가 없었다. 이동량 기반 페이지 넘김 판정을 추가했다.

**환경 주의**: 이 AVD 에는 이 서비스가 "접근성 버튼" 단축키로 등록돼 있다. 화면 오른쪽 끝(x≈996)을 탭하면 서비스가 꺼졌다(시스템 로그 `accessibility_button_targets`). 앱 결함은 아니다. 자동화 탭은 오른쪽 끝을 피한다.

- 반복 개입마다 `SUPPRESSED_BY_COOLDOWN` 행이 생겨, 세션의 첫 개입이 미뤄질 때만 남기도록 고쳤다
- 기기가 잠금 입력을 요구해 사용자에게 해제를 요청했다
- 복원 명령을 사용자가 중단했다. 변수와 상대 경로가 섞인 명령이었다. 경로를 직접 적어 다시 실행했고, 보조 파일이 없어 `rm` 은 쓰지 않았다

### 복원

시험 전 DB·설정 백업으로 되돌렸다(바이트 일치 확인: DB, 정책, 에이전트, 목표, 프로필). 앱을 연 뒤 DB v7. 세션 1, 시연 개입 3, 정책 이력 3 으로 시험 전 수와 같다. 시연 모드 켬, 볼륨 0, 접근성 연결. 시드와 시험 기록은 남아 있지 않다.

### 남은 문제

- 사용자가 직접 멈춘 영상은 시청으로 세므로, 멈춘 화면에도 쿨다운마다 개입이 뜰 수 있다
- 개입 상한이 없어 쿨다운 30초면 계속 볼 때 시간당 최대 120회다. 단계는 사용자 반응으로만 오르내린다
- 알림 방식은 답이 없으면 쿨다운마다 알림이 바뀌고 넘김으로 쌓여 단계가 빨리 오른다
- 앱을 열다 쇼츠를 거치지 않아도 잠깐 쇼츠가 보이면 `SHORTS` 로 기록될 수 있다
- 시드의 에이전트 이력은 수정 전 시드가 든 기기에서는 표시가 없을 수 있다(버전 6 이전 행)
